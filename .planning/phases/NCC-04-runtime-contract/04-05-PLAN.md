# Phase 4 Plan 5: Core Closure

<objective>
Delete the remaining native fallbacks, enforce the ownership boundary, and qualify the completed
agent runtime contract with fast deterministic gates and bounded live edges.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Enforce source ownership</name>
  <action>Remove orphaned agent-native sources, tests, fixtures, manifests, policies, and scripts from core. Add one source check that rejects standard agent IDs, package imports, native paths, and behavior switches outside reviewed release data and the isolated legacy migration. Keep core transaction and security code even when a real package is its first consumer.</action>
  <verify>The source check, test-project membership, package membership, lint, typecheck, and repository checks pass with a documented narrow compatibility allowlist.</verify>
</task>

<task type="auto">
  <name>Task 2: Run deterministic qualification</name>
  <action>Run core synthetic contract tests, all four package-only suites, all four exact-core composed suites, Fabric lanes, package-contract tests, E2E-support, changed tests, and aggregate project membership. Run broad root tests once after the ownership boundary is stable, not after every package edit.</action>
  <verify>Every declared suite runs exactly once and no package-only process can read NemoClaw source or credentials.</verify>
</task>

<task type="auto">
  <name>Task 3: Run bounded live edges</name>
  <action>Use the existing typed E2E registry. On Brev/Linux, run one canonical lifecycle per standard package: exact install, onboarding, native turn, Fabric turn when supported, inference switch, Shields, rebuild or restart, status, and cleanup. On macOS, run package discovery and selection plus one representative Docker lifecycle. Run pairing, messaging, OS, hardware, runtime-provider, or serving edges only when this phase changed that seam. Keep live messaging services excluded.</action>
  <verify>The qualification record names the exact commit, package digests, target IDs, platform, inference endpoint class, outcomes, redaction checks, and cleanup. It records failures without broad reruns.</verify>
</task>

<task type="auto">
  <name>Task 4: Publish the migration record</name>
  <action>Record files and lines moved, added, and deleted for core and each package; tests moved to each package; retained generic tests; contract operations used by each package; known unsupported capabilities; legacy exceptions; and commands run. Show the final core, package, and test trees.</action>
  <verify>The record can explain how to add a fifth package without reading implementation history.</verify>
</task>

</tasks>

<success_criteria>

- Adding an agent runtime requires a package, declared capabilities, package tests, contract tests,
  and an E2E fragment; it requires no core agent branch.
- Core changes only when NemoClaw adds a new semantic operation, not when native syntax changes.
- Deterministic tests carry semantic confidence; live tests prove only real external boundaries.
- Existing install, `harness list/install`, onboarding, native commands, and lifecycle behavior remain
  available.

</success_criteria>
