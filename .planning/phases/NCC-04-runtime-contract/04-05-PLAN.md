# Phase 4 Plan 5: Qualification and Handoff

<objective>
Qualify the Model Context Protocol (MCP), configuration, and restore contract work.
Record exact identities and leave a bounded migration sequence for remaining agent-native core
seams.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Run deterministic qualification</name>
  <action>During implementation, run `test:changed` or the focused adapter, schema, package, and synthetic tests affected by each change. Treat those results as iterative feedback. After the boundary stabilizes, run revision-pinned composition for changed packages and run `npm test` once as the aggregate non-live gate. Do not rerun package, package-contract, E2E-support, or Fabric cases that the aggregate already invokes. Run project membership, typecheck, lint, and repository checks separately because they are not assertions in the aggregate test command.</action>
  <verify>Every declared gate passes, the record counts each aggregate-covered lane once, and suite membership shows no duplicate or omitted test file.</verify>
</task>

<task type="auto">
  <name>Task 2: Run bounded host evidence</name>
  <action>On macOS, verify package discovery, zero/one/many selection, exact install, receipt inventory, and deterministic composition. Run a local Docker lifecycle only if the changed boundary needs Docker evidence.</action>
  <verify>The record names the commit, host version, commands, package identities, outcomes, and cleanup.</verify>
</task>

<task type="auto">
  <name>Task 3: Run bounded Brev evidence</name>
  <action>Use the existing typed E2E registry. Run the MCP bridge target for MCP-capable packages and existing Fabric target only when the changed path selects it. Use the validated managed-image cohort. Do not add a full package by runtime provider by serving runtime matrix. Keep live messaging services excluded.</action>
  <verify>The record names target IDs, exact package and image identities, platform, inference endpoint class, redaction result, terminal state, and cleanup. It records infrastructure failures without broad reruns.</verify>
</task>

<task type="auto">
  <name>Task 4: Record observed scope</name>
  <action>Record files and lines added, moved, and deleted; operations implemented by each package; disabled or absent capabilities; native tests moved; retained core responsibilities; compatibility exceptions; and commands run. Show the final core, package, and test trees.</action>
  <verify>A developer can trace MCP, configuration, and restore requests from core types through package builders and back to core execution without reading commit history.</verify>
</task>

<task type="auto">
  <name>Task 5: Record later migrations</name>
  <action>List the no-receipt MCP and configuration compatibility paths, Deep Agents legacy configuration helpers, remaining restore and CLI grammar, pairing, messaging projection, gateway, dashboard, closed full-startup path, and optional feature seams that still live in core. Record the shared root build assets, missing Pi-owned archive proof, and retained OpenClaw plugin runner debt. Require each later slice to define one semantic boundary, move detailed tests, and delete its native fallback. Keep external repositories and distribution behind an accepted design decision with an `Accept` outcome.</action>
  <verify>The final report does not claim that the repository is fully agent-runtime agnostic while any listed native core seam remains.</verify>
</task>

</tasks>

<success_criteria>

- MCP-capable packages implement native command construction through the typed package boundary.
- Current package configuration and OpenClaw restore operations use the same typed loader.
- Core retains authorization, execution, policy, state, transaction, and rollback.
- Fabric remains a separate package-selected headless request path.
- Deterministic evidence carries semantic confidence; live evidence covers only changed external
  boundaries.
- The report distinguishes observed contract work from the larger migration program.

</success_criteria>
