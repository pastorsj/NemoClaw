# Phase 4 Plan 1: Contract Foundation

<objective>
Create the finite agent runtime contract and remove implicit OpenClaw identity from ordinary
package-managed control flow. Reuse the current MCP host-module security boundary.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Record the local trust boundary</name>
  <action>Record the user's direction as authority for this local product-scope candidate. Name the trusted-package assumption, fixed paths and exports, VM and output limits, validation environments, rollback, and exclusion of arbitrary callbacks. State that the work is not canonical or supported NemoClaw behavior and that any upstream or support proposal still requires its own accepted product decision.</action>
  <verify>The local record is bound to the planning revision, contains every boundary field, and makes no upstream support claim.</verify>
</task>

<task type="auto">
  <name>Task 2: Add the finite adapter foundation</name>
  <action>Add `adapter/contract.ts` for the closed operation names and shared rules, `adapter/schema.ts` for bounded input and output validation, `adapter/loader.ts` for fixed-path receipt validation and the VM boundary, and `adapter/mcp.ts` for the first concrete operation. Fold the current MCP-only loader into these files without changing MCP behavior. Do not predeclare later request/result types, add a generic hook, or accept a manifest-selected path. A later operation enters the map only in the package slice that wires its current consumer and tests.</action>
  <verify>MCP boundary tests cover missing and unknown operations, malformed exports, imports, code generation, byte limits, output limits, receipt drift, and mutation races.</verify>
</task>

<task type="auto">
  <name>Task 3: Require explicit runtime identity</name>
  <action>Carry one real AgentDefinition and exact package identity through package-managed onboarding, lifecycle, status, policy, messaging, rebuild, backup, restore, and command dispatch. Move old `agent: null` translation into one named legacy migration and stop using null as runtime behavior in ordinary paths.</action>
  <verify>Focused state and lifecycle tests prove fresh, resumed, restored, rebuilt, and failed operations retain the same explicit identity before every mutation.</verify>
</task>

<task type="auto">
  <name>Task 4: Prove generic composition</name>
  <action>Add one inert synthetic package fixture that implements every currently defined contract operation. Exercise it through core without a production agent ID, then add source checks that reject new package-ID switches, package imports, manifest-selected executable paths, and unreviewed operation names.</action>
  <verify>Core contract, package safety, source architecture, typecheck, and repository checks pass.</verify>
</task>

</tasks>

<success_criteria>

- The contract has one name and one implementation path; it has no V1/V2 classes or loaders.
- Core owns authorization and execution; helpers return only bounded plans or parsed results.
- The legacy OpenClaw mapping is isolated and cannot affect new package-managed state.
- Later package moves reuse the loader and add a typed operation only with a current consumer and
  test; they need no agent-name branch.

</success_criteria>
