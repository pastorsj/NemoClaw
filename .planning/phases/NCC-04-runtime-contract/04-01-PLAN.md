# Phase 4 Plan 1: Contract Foundation

<objective>
Stabilize the existing typed adapter boundary and state its trust model before moving native
operations out of core.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Record the architecture boundary</name>
  <action>Document the core, package, and Fabric responsibilities. State the trusted-package assumption, receipt checks, fixed paths and exports, VM limits, request and result bounds, execution authority, rollback ownership, and product-scope status.</action>
  <verify>The package guide and phase context describe one boundary with no lifecycle callback, event bus, manifest-selected host adapter, or support claim.</verify>
</task>

<task type="auto">
  <name>Task 2: Stabilize the typed loader</name>
  <action>Keep `adapter/contract.ts`, `adapter/schema.ts`, and `adapter/loader.ts` as the only generic host-module path. Core defines module paths, exports, TypeScript request and result types, runtime schemas, and limits. The loader resolves a pinned receipt, validates the package tree before and after read, passes no host capabilities or import loader, disables string and WebAssembly code generation, and validates frozen JSON values at both boundaries. Record that package `.cts` implementations are runtime-validated CommonJS source and are not compiled by the package TypeScript configurations.</action>
  <verify>Focused tests reject invalid contracts, links, special files, oversized source, invalid UTF-8, required imports, code generation, malformed requests, malformed results, receipt drift, and post-read mutation. The guide does not claim compile-time checking for package `.cts` source.</verify>
</task>

<task type="auto">
  <name>Task 3: Bind package identity</name>
  <action>Require the package identity recorded for the sandbox before loading Model Context Protocol (MCP), configuration, or restore adapters. Resolve the agent definition from that receipt. Reject an identity, manifest, capability, adapter, or receipt mismatch. Do not infer OpenClaw or another package from missing identity. For a configuration transaction, retain the receipt-pinned definition and plan through validation, then verify both under the mutation lock.</action>
  <verify>Positive and negative tests prove that a package-backed sandbox can load only its own receipt-pinned adapter. Configuration tests prove that an active-pointer change cannot redirect the transaction and reject a sandbox-receipt or plan change before the write.</verify>
</task>

<task type="auto">
  <name>Task 4: Preserve the core executor</name>
  <action>Keep OpenShell clients, credential custody, policy mutation, command execution, inspection authority, transaction state, rollback, and redacted diagnostics outside the adapter loader. Helpers return bounded values only.</action>
  <verify>Source and behavior tests show that the loader receives no OpenShell client, secret value, transaction object, rollback callback, or filesystem handle.</verify>
</task>

</tasks>

<success_criteria>

- One contract and loader own the executable package boundary.
- MCP is the first proving capability. MCP, configuration, and restore operations have current
  consumers.
- Package identity is explicit before executable helper code is read.
- The VM is documented as a capability limit, not a hostile-code sandbox.

</success_criteria>
