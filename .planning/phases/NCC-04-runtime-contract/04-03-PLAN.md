# Phase 4 Plan 3: Contract Evidence

<objective>
Make the typed boundary reusable through synthetic conformance, package ownership, and fast
deterministic tests.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Add synthetic conformance</name>
  <action>Create inert package fixtures with IDs that core does not know. Implement the MCP, configuration, and restore operations at their fixed paths. Exercise valid calls, absent capabilities, missing modules, unknown fields, malformed exports, invalid values, and size limits through the public loader. For configuration, cover per-leaf URL policy, command proof kinds, receipt and plan pinning, and finite restore write plans.</action>
  <verify>The fixture passes without a production catalogue row, agent switch, package import, or manifest-selected host module.</verify>
</task>

<task type="auto">
  <name>Task 2: Move native protocol tests</name>
  <action>Keep Model Context Protocol (MCP) command grammar, runtime configuration plans, URL-path decisions, restore merge grammar, protected-file declarations, native reload, and package-specific failure assertions under each package's `tests/host`, `tests/runtime`, or `tests/integration` directory. Keep generic transaction, SSRF, credential, policy, rollback, and redaction assertions in core.</action>
  <verify>Package test commands own native assertions, while root tests refer to typed requests, results, and black-box outcomes.</verify>
</task>

<task type="auto">
  <name>Task 3: Enforce source ownership</name>
  <action>Keep one metadata-derived source check that rejects imports from core into agent runtime packages. Keep the reviewed one-use migration exception explicit. Use contract tests, not a broad source-text ledger, to reject manifest-selected host adapters and invalid operation names.</action>
  <verify>The layer check fails on synthetic static, re-export, require, dynamic, and relative package imports and passes on the reviewed exception.</verify>
</task>

<task type="auto">
  <name>Task 4: Enforce suite ownership</name>
  <action>Keep Vitest project globs disjoint and exhaustive. Ensure package-only tests run without root source. Treat direct `test:nemoclaw` as ambient-checkout composition; use `scripts/packages/checkout.mts composed` when evidence must name one immutable core revision. The default package command must not run direct Fabric tests separately because its composed Fabric lane already includes them.</action>
  <verify>`npm run test:projects:check`, package-only rehearsal, revision-pinned composed rehearsal, and package-contract tests pass. Command inspection confirms that `npm test` reaches direct Fabric cases through `test:nemoclaw` and `test:fabric:composed` only once.</verify>
</task>

</tasks>

<success_criteria>

- A developer can copy the in-tree package structure and implement the current contract from its
  core types, runtime schemas, and tests.
- A package-native change can be qualified without the broad root suite.
- Core tests assert semantic outcomes instead of native syntax.
- Core-to-package import regressions fail before live E2E.

This plan does not prove an independent Docker build. Current Dockerfiles still consume reviewed
assets from the NemoClaw root build context.

</success_criteria>
