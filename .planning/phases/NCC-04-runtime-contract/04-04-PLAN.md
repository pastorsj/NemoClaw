# Phase 4 Plan 4: Fabric and Image Evidence

<objective>
Preserve NeMo Fabric for headless request execution and bind live evidence to exact published
images without expanding the host adapter contract.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Verify the Fabric boundary</name>
  <action>Confirm that core selects only the receipt-pinned manifest headless command. Keep adapter selection, dependency locks, generated Fabric configuration, credential environment names, and native assertions in the package. Keep the generic runner free of agent-name and adapter-ID branches. Do not route lifecycle, startup, configuration, restore, MCP, messaging, pairing, or durable state through Fabric.</action>
  <verify>Fabric runner tests and source checks prove that adding a package configuration does not add a core or runner branch.</verify>
</task>

<task type="auto">
  <name>Task 2: Run package Fabric lanes</name>
  <action>Use `test:fabric` for focused adapter feedback. Use the default package command for aggregate evidence; its `test:nemoclaw` lane runs composed Fabric tests, which include the direct cases. Preserve the native command for a composition that its Fabric adapter cannot represent.</action>
  <verify>Valid runs, unavailable compositions, literal-credential rejection, result bounds, timeout, cancellation, redaction, and artifact cleanup pass at their earliest stable test boundary.</verify>
</task>

<task type="auto">
  <name>Task 3: Verify package receipts</name>
  <action>Exercise exact install, immutable object and receipt publication, active pointer resolution, tree revalidation, and exact reinstall. Keep publisher authentication outside the local receipt claim. Record that Pi's materialized and packed-root artifact proof remains in the root package-contract suite until Pi gains a package-owned archive test.</action>
  <verify>Package-store and compiled package-contract tests pass for valid, conflicting, missing, and mutated receipt state. The record does not claim package-owned Pi archive proof.</verify>
</task>

<task type="auto">
  <name>Task 4: Verify the managed-image gate</name>
  <action>Require stock live jobs to depend on managed-image publication. Validate one cohort revision and workflow attempt, the complete shipped-agent set, both published Linux architectures, immutable image and base references, descriptors, and attestations. Pass the same receipt and revision to every stock consumer.</action>
  <verify>Workflow-boundary tests reject a missing dependency, partial cohort, mixed revision, mutable reference, invalid attestation binding, or consumer receipt mismatch.</verify>
</task>

<task type="auto">
  <name>Task 5: Keep candidate evidence separate</name>
  <action>Do not use the shipped cohort receipt to qualify Pi while Pi remains outside that cohort. Require exact candidate image evidence for a Pi live run.</action>
  <verify>The qualification record distinguishes shipped-cohort evidence from Pi candidate evidence.</verify>
</task>

</tasks>

<success_criteria>

- Fabric remains headless request execution, not a package loader or control plane.
- Package, Fabric, and image identities remain distinct and traceable.
- Deterministic Fabric tests carry behavior confidence before a live run.
- Stock E2E cannot consume a partial or mixed managed-image publication.

</success_criteria>
