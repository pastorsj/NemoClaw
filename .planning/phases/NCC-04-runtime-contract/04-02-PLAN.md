# Phase 4 Plan 2: Model Context Protocol Migration

<objective>
Use Model Context Protocol (MCP) as the first proving package capability. Remove package-backed
native translation fallbacks from core.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Freeze MCP semantics</name>
  <action>Keep the seven current operations: `register`, `remove`, `inspect`, `mutationCapability`, `teardownCapability`, `verifyRuntimeIntent`, and `runtime`. Registration uses `buildMcpRegistrationPlan`; removal uses `buildMcpRemovalPlan`; runtime-intent verification uses `describeMcpRuntimeIntentVerification`; runtime uses `buildMcpRuntimeCommand` and returns an argument vector that core quotes. Map each operation to its current core consumer. Do not add reload or reconciliation callbacks; core owns those workflows.</action>
  <verify>Every operation names one consumer, fixed module path, export, typed request, typed result, size limit, and negative test.</verify>
</task>

<task type="auto">
  <name>Task 2: Migrate Hermes first</name>
  <action>Route Hermes package-backed MCP command construction through `packages/nemoclaw-hermes/host/mcp-adapter.cts`. Preserve native transaction and reload semantics. Prevent the receipt-backed route from using the native core translator after package tests protect the behavior. Keep the native translator only in the named no-receipt compatibility path.</action>
  <verify>Hermes package, loader, registration, removal, reconciliation, rollback, and failure tests use the installed package implementation.</verify>
</task>

<task type="auto">
  <name>Task 3: Migrate OpenClaw and LangChain Deep Agents Code</name>
  <action>Route OpenClaw and Deep Agents Code through their fixed package adapters. Preserve each native grammar and result shape inside its package. Remove each receipt-backed route from the core translation and adapter-ID switch. Retain no-receipt compatibility dispatch until its upgrade boundary is defined.</action>
  <verify>Both packages pass positive, replacement, removal, rollback, malformed-result, and receipt-drift tests through exact installed identities.</verify>
</task>

<task type="auto">
  <name>Task 4: Keep Pi MCP-disabled</name>
  <action>Keep Pi's manifest MCP capability disabled. Return a typed validation error before adapter load. Do not add an empty adapter or an agent-name exception.</action>
  <verify>A Pi package fixture and an unknown package fixture both reach the same capability-based validation refusal.</verify>
</task>

<task type="auto">
  <name>Task 5: Preserve core transactions</name>
  <action>Keep endpoint validation, credential placeholders, policy generation, credential revision convergence, OpenShell execution, durable requested state, inspection authority, rollback, and redacted errors in core. Replace only native translation.</action>
  <verify>Core integration tests cover failed apply, failed inspection, failed reload, rollback, and unchanged durable state without asserting package-native syntax.</verify>
</task>

</tasks>

<success_criteria>

- An installed package selects MCP behavior by capability and receipt, not by agent ID.
- Each package owns native MCP syntax and detailed tests.
- Core owns the product transaction and contains no package-backed command fallback.
- A missing MCP capability fails closed with a typed validation error before adapter load.
- The record names `mcp-bridge/legacy-mutation.ts`, its agent-adapter dispatcher, and Deep Agents
  legacy configuration helpers as no-receipt migration debt.

</success_criteria>
