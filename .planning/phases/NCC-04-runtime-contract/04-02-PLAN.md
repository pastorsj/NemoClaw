# Phase 4 Plan 2: Hermes Extraction

<objective>
Make `packages/nemoclaw-hermes` the sole owner of Hermes-native behavior while preserving current
commands, lifecycle, and no-messaging qualification behavior.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Complete Hermes package ownership</name>
  <action>Move remaining Hermes policy, model setup, configuration, gateway, dashboard, pairing, MCP, state, SQLite and cron, skill, broker, compatibility, and runtime assets into the existing responsibility folders. <task type="auto">

  <action>Implement only the contract operations Hermes needs. Keep configuration generation and guards inside the image when possible. Delete the corresponding Hermes switches and fallback translations from core.</action>
  <verify>Hermes native, Fabric, config integrity, MCP, restore, gateway, broker, and failure tests pass through the package implementation with old core paths absent.</verify>
</task>

<task type="auto">
  <name>Task 3: Move detailed Hermes tests</name>
  <action>Move every Hermes-native root test, fixture, helper, and assertion to `packages/nemoclaw-hermes/tests` or the language-native plugin test location. Add deterministic messaging projection tests without contacting a messaging service.</action>
  <verify>Package-only, composed, Fabric, plugin, archive, image, exactly-once suite membership, and core changed-test lanes pass.</verify>
</task>

</tasks>
