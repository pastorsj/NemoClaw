# Phase 2 Plan 03: Immutable Package Store

<objective>
Install one verified harness package through a crash-safe, digest-addressed local store.

Purpose: CLI, onboarding, and installer work need one exact transaction whose failure never damages
the previously active package and whose reads never trust pointer metadata alone.

Output: Strict receipt records, immutable object storage, receipt-verified lookup by active pointer
or explicit digest, and one idempotent install service.
</objective>

<threat_model>

- **T-03-01 — Partial activation (critical):** A crash makes unverified bytes active. Mitigation:
  object and receipt publication precede the final atomic pointer replacement.
- **T-03-02 — State-root substitution (critical):** Links or ancestor replacement redirect writes.
  Mitigation: no-follow authority checks before and after the transaction.
- **T-03-02A — Split inventory (high):** A gateway-port override hides installed harnesses.
  Mitigation: derive the store from the global base state root and test port invariance.
- **T-03-03 — Concurrent mixed install (high):** Two installers publish crossed receipts/pointers.
  Mitigation: per-harness cross-process lock and identity verification at commit.
- **T-03-04 — Silent fallback (high):** Corrupt active state falls back to bundled or OpenClaw.
  Mitigation: every read fails closed; only explicit install repairs state.
- **T-03-05 — Secret persistence (high):** Ambient credentials enter receipts. Mitigation: closed
  serializers and negative credential-shaped tests.
- **T-03-06 — Version identity conflict (high):** One package version names different bytes.
  Mitigation: bind each harness ID and package version to one retained digest.

</threat_model>
