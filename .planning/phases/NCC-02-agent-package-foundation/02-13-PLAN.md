# Phase 2 Plan 13: Writer-Locked Session Package Binding

<objective>
Bind fresh and directly resumed standard sessions to exact package authority under the existing
writer lock without overwriting the session and registry bytes required by portable recovery.

Purpose: Selection is authoritative only when read-only package proof precedes recovery, portable
recovery consumes the original durable authority, and the first package write cannot race an active
pointer or occur after ordinary onboarding work begins.

Output: A shared state migration service, explicit migration provenance, identity-aware fresh
session creation, and source-backed lock-order tests.
</objective>

<threat_model>

- **T-13-01 — First-write race (critical):** The active pointer changes between selection and save.
  Mitigation: exact re-resolution and persistence under the existing writer lock.
- **T-13-02 — Authority overwrite before recovery (critical):** Fresh save or legacy CAS changes the
  exact session/registry bytes that portable recovery must consume. Mitigation: read-only package
  proof precedes `.run()`, while all owner writes happen inside its recovered operation.
- **T-13-03 — Historical provenance invention (high):** Legacy mapping claims old bytes.
  Mitigation: explicit `legacy-current-bundle` provenance only.
- **T-13-04 — Destructive fresh failure (high):** `--fresh` clears state before discovering no
  installed harness. Mitigation: selection succeeds before `clearSession`.
- **T-13-05 — Split legacy authority (critical):** Session and registry retain different package
  identities after a crash. Mitigation: deterministic lock order, atomic owner writes, peer
  adoption, and partial-crash convergence tests in the shared service.

</threat_model>
