adding installation or onboarding behavior yet.

Purpose: The first public package surface should be a deterministic read-only view whose code makes
availability, installation, and selection visibly different concepts.

Output: One inventory model, human and machine renderers, the `harness` topic, and the public list
command.

  <action>Build `createHarnessInventoryView` as one stable inventory model from the Plan 02-04 catalogue, then keep text and JSON formatting as focused functions in the same small file. Render separate `Installed` and `Available` sections without turning available content into installed or supported content. Empty installed state says that no harnesses are installed and still shows reviewed available artifacts. Human installed rows expose bounded ID, display name, adapter package version, contract version, and a shortened digest; available rows say whether that exact bundled identity is active or differs. The hidden machine form uses one closed, versioned top-level schema with separate `installed` and `available` arrays. Every installed row carries the full exact `HarnessPackageIdentity` (`kind`, canonical `id`, `packageVersion`, `contractVersion`, and lowercase 64-hex `contentDigest`) plus its closed health state; only human text shortens the digest. Reject extra keys when parsing that machine form. Report damaged installed state explicitly, filter terminal controls, and never render receipt paths, source paths, or credentials. Accept catalogue input as a dependency so source tests use in-memory records/private temporary roots and remain valid when `dist/harnesses` and the user's real package store are absent.</action>
  <verify>`npx vitest run --project cli src/lib/harness/package-list.test.ts`</verify>
  <acceptance_criteria>
    - Empty, one, multiple, version-different, and damaged inventories have deterministic assertions.

    - Machine installed rows preserve the complete exact identity and full digest; only human text shortens it.
    - Text and JSON derive from one model and contain no absolute path, credential, or unfiltered control character.
    - Tests do not read `dist/harnesses` or write beneath the developer's HOME.
  </acceptance_criteria>

<threat_model>

- **T-05-01 — Terminal injection (high):** Package metadata controls output. Mitigation: bounded,
  control-filtered model fields and negative fixtures.
- **T-05-02 — Ambient availability (high):** A global module or checkout directory appears in the
  list. Mitigation: catalogue-only dependency and ambient-module negative tests.
- **T-05-03 — Corruption masking (high):** Damaged installed state appears merely uninstalled.
  Mitigation: explicit damaged result with no bundled fallback.
- **T-05-04 — Source-test host mutation (high):** Tests use the real store. Mitigation: injected
  catalogue data/private roots and assertions that HOME and `dist/` are untouched.

</threat_model>
