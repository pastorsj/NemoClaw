# Phase 2 Plan 20: Prepared Rebuild Authority

<objective>
Consume exact harness package authority from rebuild manifests and carry one pinned definition from
rebuild preflight through prepared recovery and target configuration.

Purpose: Rebuild is destructive and resumable. Agent name alone cannot prove which package bytes
created a backup or authorize deletion after a process restart.

Output: Two-boundary prepared-recovery checks and a package-bound target context ready for
downstream consumers.
</objective>

<threat_model>

- **T-20-01 — Manifest downgrade (critical):** Prepared recovery accepts a manifest whose package
  identity is omitted or malformed. Mitigation: consume Plan 19's versioned exact schema and keep
  legacy and candidate states distinct.
- **T-20-02 — Preflight-to-delete swap (critical):** Registry or object changes after validation.
  Mitigation: independent immediate pre-delete reread and equality check.
- **T-20-03 — Ambient definition reload (critical):** Rebuild uses checkout or active bytes.
  Mitigation: one pinned definition carried in the target context.
- **T-20-04 — Candidate coercion (high):** Candidate state is interpreted as standard absence.
  Mitigation: explicit qualified candidate branch with regression tests.
- **T-20-05 — OpenClaw sentinel coupling (critical):** A non-null package definition disables the
  OpenClaw credential-family path. Mitigation: explicit effective-agent identity plus OpenClaw and
  non-OpenClaw target-runtime tests.

</threat_model>
