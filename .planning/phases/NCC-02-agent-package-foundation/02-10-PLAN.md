# Phase 2 Plan 10: Pinned Agent Definitions

<objective>
Create one root-parameterized AgentDefinition path and a focused resolver that separates durable
compatibility fields from the exact effective definition used by package-managed sandboxes.

Purpose: Installed package bytes cannot become authoritative while definition loading still assumes
the repository root or while `agent: null` is overloaded as both compatibility state and runtime
selection.

Output: A shared definition builder plus exact sandbox-agent resolution with no executable package
dispatch.
</objective>

<threat_model>

- **T-10-01 — Root substitution (critical):** An installed manifest resolves assets from repository
  bytes. Mitigation: explicit trusted root plus containment checks for every derived path.
- **T-10-02 — Cache aliasing (critical):** The same harness ID returns a definition from another
  digest. Mitigation: root/object-aware cache authority or no installed-definition cache.
- **T-10-03 — Null-sentinel fallback (high):** `agent: null` silently selects current OpenClaw.
  Mitigation: retain the sentinel but require separate exact package identity for package-managed
  rows.
- **T-10-04 — Candidate promotion (high):** Pi or NemoCUA becomes ordinary installed inventory.
  Mitigation: preserve current qualification gates and null package authority.

</threat_model>
