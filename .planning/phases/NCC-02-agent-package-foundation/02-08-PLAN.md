# Phase 2 Plan 08: Session Package Identity

<objective>
Make exact harness identity and honest legacy-migration provenance representable in onboarding
sessions and checkpoints before orchestration begins depending on them.

Purpose: Fresh selection and later legacy reconciliation need one strict durable shape that cannot
drop malformed values, persist secrets, or claim knowledge of historical package bytes.

Output: Shared identity/provenance normalization, a tested fresh session write seam, and compatible
checkpoint schema version 5.
</objective>

<threat_model>

- **T-08-01 — Schema downgrade (high):** Malformed identity is discarded as legacy absence.
  Mitigation: explicit absent/valid/invalid parsing and negative normalization tests.
- **T-08-02 — Partial identity substitution (critical):** Only ID or digest is compared. Mitigation:
  equality across kind, ID, package version, contract, and digest.
- **T-08-03 — False historical provenance (high):** Migration claims current bytes created an old
  sandbox. Mitigation: fixed `legacy-current-bundle` source and a record with no historical digest
  field.
- **T-08-04 — Secret persistence (high):** Ambient values enter durable records. Mitigation: closed
  secret-free schemas and credential/path/URL rejection.
- **T-08-05 — Fresh-write field loss (critical):** `createSession` binds identity but `saveSession`
  drops it. Mitigation: real fresh-write round-trip tests.

</threat_model>
