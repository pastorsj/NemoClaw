<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Prior persisted state to current package selection | Legacy user state can select code and images only after exact migration. |
| Replacement runtime to authoritative sandbox | A staged runtime must not seize authority or delete the prior runtime before verified publication. |
| Destructive CLI intent to retained resources | One deletion request must not imply deletion of packages, snapshots, images, or durable state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-08-04-01 | Spoofing | Legacy package migration | mitigate | Map only complete, non-contradictory evidence to one exact release-set tuple and reject defaults. |
| T-08-04-02 | Tampering | Replacement publication | mitigate | Bind the production journal, existing authority checks, and compensation to exact prior, replacement, and effect receipts. |
| T-08-04-03 | Elevation of privilege | Compensation | mitigate | Delete only resources proven owned by the replacement transaction; preserve reused and foreign resources. |
| T-08-04-04 | Denial of service | Interrupted upgrade | mitigate | Keep the prior sandbox authoritative until readiness and durable publication; make recovery idempotent. |
| T-08-04-05 | Repudiation | Destructive lifecycle | mitigate | Record the named operation, references checked, decision, and redacted result before mutation. |
| T-08-04-06 | Spoofing | Replacement readiness | mitigate | Require a package executor claim and a distinct OpenShell-controlled observation with producer identity and limitations. |
| T-08-04-07 | Elevation of privilege | Qualification and support | mitigate | Preserve immutable qualification evidence and require static `supported` status at the mutation edge. |
</threat_model>
